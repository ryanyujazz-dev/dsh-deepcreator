# App Stage 受控能力权限模型（提案）

**状态：non-normative 提案（v0.0.1，M6d 设计轮产出）。** 本文不是规范：词表、schema、列示规范均未定案，实现前不生效。与规范文档（app-stage.md）冲突时以规范文档为准；本文的存在价值是把 Phase 3 遗留的"受控能力权限模型"从一句话扩展成可对抗评审的具体形状，供下次修订拍板。

**实现纪律（先于一切词表）**：审批卡在本提案定案前**不得渲染权限区块**（manifest v1 的 `permissions` 恒空，渲染空表=承诺幻觉）；运行时桥的 **undeclared=拒绝** 语义与任何权限的放行实现必须落在**同一里程碑**——只放行不设闸，或只设闸不放行，都制造"文档承诺>实现"的债（M6 对抗审计安全项 #9）。

## 1. 问题与不变量

应用→DeepCreator 方向的能力（读工作区、触发 agent、通知面）目前为零（v0.0.6 拍板）。开放它们的前提是每项能力都能回答三个问题：**谁授权**（安装时一次性 vs 每次调用）、**谁审计**（能力调用必须有与 `app_invoke` 同级的留痕面）、**谁可撤销**（卸载/降级时能力随 app 消失，不留悬垂授权）。

不变量（提案级，评审对象）：

1. **声明先于行使**：manifest 未声明的能力，运行时桥一律拒绝（undeclared=deny），错误码可行动。
2. **授权面唯一**：能力的授予只发生在安装/更新的审批卡上（发布链的审批是唯一人类确认缝）；不存在"事后在应用里再授权"的第二入口（那会分裂信任根）。
3. **衰减单调**：更新版本收窄权限=随更新生效；**扩宽权限=强制重走审批**（digest 变化已过闸，但权限集变化必须显式可见——审批卡 diff 权限增量）。
4. **技能包对称**：已安装应用作为 agent 技能包消费时，agent 侧能力调用继承同一权限面——agent 不是提权通道（`app_invoke` 传参不能携带应用未声明的能力语义）。
5. **回退不复活旧权限**：回退到旧版本时，若旧版本权限集更宽，**拒绝回退或要求确认**（回退是代码切换，不是授权回退）。

## 2. 词表候选（第一批评审对象）

命名形状：`<域>.<动作>`，全小写点分；通配符**不进第一版**（审计面无法枚举通配）。

| 候选 | 语义 | 授权粒度 | 评审疑点（红队待答） |
|---|---|---|---|
| `workspace.read` | 读本 app 发布来源工作区的文件树快照（只读、无 glob 透传——词表自带路径域，不接受应用自定 glob） | 安装时 | 工作区是会话级概念，installed app 跨会话存活——"来源工作区"消失后能力指向什么？候选答案：能力随来源工作区不可达而**自动失效**（不是悬垂报错） |
| `agent.trigger` | 经受限桥触发一次 agent 会话事件（携带结构化载荷，非自由 prompt） | 安装时 + 首次调用确认 | 与 `app_invoke` 的方向恰好相反；载荷结构必须 schema 化，否则=自由 prompt 注入面 |
| `notify.badge` | 在 Launcher 卡角标显示应用自持数字（自持数据投影，非系统通知面） | 安装时 | 是否真需要权限？角标是应用自持数据的呈现，可能归"自持数据机制"而非能力桥（与 AppData 同族=不需权限）——倾向从词表撤下 |
| `notify.system` | 系统级通知（Desktop 通知面） | 安装时 + 频控常数 | 钓鱼/骚扰面；若进词表，频控与撤回语义先定 |

第一版建议：**只进 `workspace.read` 与 `agent.trigger` 两个**，且都带"安装时+运行时首次确认"双闸（重交互、低频能力才配得上双闸成本）。

## 3. manifest v2 schema 草案（non-normative）

```jsonc
{
  "id": "kanban-demo",
  "version": "0.3.0",
  "schema": 2,                        // 缺省 1；v1 阅读器遇 2 → MANIFEST_SCHEMA_FUTURE 拒装（可行动错误）
  "permissions": [                     // v1 恒空数组；v2 只允许词表内的字面量，无对象无通配
    { "capability": "workspace.read", "scope": "source-workspace" },
    { "capability": "agent.trigger", "scope": "declared-actions" }
  ]
}
```

要点：`scope` 是**词表预定义域枚举**，不是应用自由字符串（防 scope 变相 glob）；未识别 capability → `MANIFEST_PERMISSION_UNKNOWN` 拒装（fail-closed，不静默忽略）；schema 字段使 v1→v2 可判读迁移。

**回退交互**（不变量 5）：回退目标版本 schema=2 且权限集 ⊃ 当前权限集 → 确认对话加"此版本声明的能力多于当前版本"行；v1→v2 回退天然收窄（v1 无权限），无阻。

## 4. 大对象逃生通道评估（结论）

Phase 2 已定案的现实：AppData 单值 256KiB / 文档 4MiB / CSP `self`；大对象走运行时资产目录（agent 写入、AppData 存引用）。**结论：不需要为大对象开能力权限**。理由：字节搬运的需求已由资产通道满足且写入方是 agent（审计面完整）——若为应用自写大对象开 `storage.large` 类能力，等于把 agent 的审计位让渡给不可信应用代码，收益为零（应用自身无生成大对象的真实场景：生成类组合=会话生成→资产通道→invoke 放置）。**逃生通道=资产通道，不是权限**。重开此题的唯一触发条件：出现"应用运行时自身产出大对象且必须持久化"的真实场景——届时先评审 `asset.self-write`（限 per-app 配额内），仍非通用存储权限。

## 5. 审批卡权限列示规范（定案前以本节为评审底稿）

- 权限区块列**词表字面量 + 人话一行**（locale 化），不渲染原始 JSON；零权限 → 区块整块不出现（不渲染"无权限"空表）。
- 更新审批：权限**增量 diff** 视觉优先（新增=警示色标注，移除=次级删除线），全集折叠。
- 导入事实卡：权限列示与发布审批卡同规范（导入来源无工作区指纹背书，`workspace.read` 对导入包**自动失效**——无来源工作区可指）。
- 拒绝入口永远与确认同级（能力授权不可"仅本次允许"——避免授权疲劳训练）。

## 6. 未决问题（下次修订输入）

1. `agent.trigger` 的载荷 schema 归属：manifest actions 内声明 per-action payload schema，还是能力词表统一 schema？
2. 权限撤销的联动面：卸载=能力消失（已定）；**来源工作区删除/改名**时 `workspace.read` 的自动失效事件源是谁（watcher 面 vs 调用时校验）？
3. 审批卡 diff 所需的"上一版本权限集"从哪读：history.jsonl 增量记录 manifest 摘要（+每条记录体积）还是按需从版本目录回读 manifest（零增量、回读 O(1)）——倾向后者。
4. Desktop 通知面（`notify.system`）是否永远不进词表（频控/撤回/钓鱼三项成本 vs 无已证实需求）。

## 7. 评审记录

- **红队评审（M6d 设计轮，v0.0.1）**：总裁决「需修订后再评」——骨架可保留，1 致命 + 7 高 + 5 中 + 3 低须关闭后方可晋升 v0.0.2。关键发现（修订时逐条落法）：
  - 致命 F1：`workspace.read` 快照时点/路径域/内容形态三轴全空，且与规范文自认未封死的自导航外泄通道（开放问题 3）构成「读工作区 → URL 外带」完整链——必须钉死三轴并写死 IAB 化前置（未封自导航前该能力不上桌）。
  - 高 H1：不变量 3 与现行 update-same-source 免确认档脱焊——同源更新加权限会静默安装；落法：权限目标集 ≠ 当前集时降档至硬审批。
  - 高 H2：不变量 2 与 5 矛盾（回退确认=第二授权入口）；落法：回退目标权限集为当前超集时**一律拒绝**（错误码可行动），不做确认分支。
  - 高 H3：超集谓词漏不可比集，改集合差非空；回退闸的权限读源定为版本目录 manifest 回读。
  - 高 H4：`agent.trigger` scope 只封信促不封载荷 string；不变量 4 方向修正——真提权路径是 agentGuide/触发载荷牵引 preset 会话，非 app_invoke 方向。
  - 高 H5：fail-closed 补未知 scope、capability-scope 配对校验、重复条目、缺字段、schema 非法值。
  - 高 H6：导入路径对 `agent.trigger` 缺位——不可信 origin 的导入即授 agent 桥；落法：导入包的 `agent.trigger` 一律按未声明处理（导入无工作区背书，同 `workspace.read` 自动失效逻辑）。
  - 高 H7：「与 app_invoke 同级留痕」不成立（iframe 内发起无转录面）；落法：host 侧 per-app 能力调用日志，活动时间线消费。
  - 中 M1：schema 协商描述了不存在的机制（现行校验器静默忽略未知字段；schema:2+空 permissions 今日可静默过闸）——修订时把 v1 校验器对 `schema`/`permissions` 的现行行为如实写为基线，v2 机制为提案。
  - 中 M2：卸载删水位+历史 → 两步绕过不变量 5；修订时如实声明现行边界并评估水位随卸载保留的代价。
  - 中 M5：未决清单补六项（接收端语义/快照三轴晋升/调用预算/首确状态与重置/桥协议版本协商/per-capability 撤销的不做决定）。
  - 修订轮落位于 M6 收尾或 Phase 4 初，本文件保持 non-normative。
