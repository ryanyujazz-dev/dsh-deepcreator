# 决策备忘录：声明式渲染器扩展位（Px-δ）

**状态：决策记录（M6f）。** Phase 3 遗留项的裁决。规范引用：app-stage-presence.md v0.0.4 L178（Px-δ hints 与回放，挂 Phase 3）、app-stage.md v0.0.6 L229。

## 背景

Px-δ 原案四件套：manifest `ui` hints 契约（诚实性梯度 a 档——应用自述的静态声明）、field→key 映射、时间线回放 UI、字段级协作模式、带归属框架的"应用自述"播报评估。M6 到位后评估是否启动。

## 裁决：**拆分处置——`ui` hints 契约随 M6d 权限模型修订轮一起定 schema；回放 UI 与字段级协作缓裁，挂起条件写死**

理由：

1. **`ui` hints 与 manifest v2 是同一个 schema 决策。** M6d 提案的 manifest v2（`schema: 2` + 结构化 `permissions`）与 `ui` hints 字段共享同一次版本协商、同一套 fail-closed 校验、同一张审批卡列示。分两次改 manifest 版本是纯摩擦——合并进 M6d 修订轮（该文档未决问题清单已含 schema 协商）。
2. **回放 UI 的前置是归因可靠性，前置未满足。** 时间线回放要求每帧画面可归因到具体命令/数据版本；当前 AppData 是文档级版本（rev），无字段级归因。字段级归因（H7 能力日志的同族问题）是 M6d 修订轮的输入之一——回放 UI 在其后，不并行。
3. **字段级协作模式无第一手场景。** 与无人值守裁决同一逻辑：没有用户亲述的周频真实场景（两人同时编辑同一应用的同一字段），不建并发语义。现有粗粒度（journal 键路径级事件广播）已覆盖"多实例最终一致"。

## 触发重开的条件

- `ui` hints：M6d 权限模型修订轮启动即并入（无独立触发）；
- 回放 UI：字段级归因进入可实现状态（能力日志定案后）；
- 字段级协作：用户亲述周频场景，或出现官方协作原语。

## 对现状的约束

- manifest v1 的 `ui` 字段现状（若校验器容忍未知字段，则今日manifest 可携带任意 `ui` 而无人消费）**不构成承诺**：v2 定案前客户端不读不渲染 `ui` hints，文档不描述其效果。
- 本备忘录不产生任何代码变更。
