# DeepCreator architecture

DeepCreator is a presentation distribution over the official DeepSeek Harness runtime. The official process owns Agent execution, Session persistence, RPC, Settings, Workspace data, Client Runtime objects, and Slot rendering. DeepCreator owns Electron and the UI plugin rows listed by `@ryanyujazz/dsh-deepcreator-web`.

Session pinning remains presentation state in ui-workspace's persisted browser view store; it moves a Session row into a sibling pinned region without mutating official Workspace membership or Session persistence. Native folder opening stays on the official boundary: ui-workspace observes `connection.hostDescription.canOpenPath` and calls `ctx.workspaces.openPath`, whose Host implementation delegates to Finder, Explorer, or `xdg-open`; DeepCreator adds no Electron-private path-opening channel.

Session deletion is the one lifecycle verb the official harness does not expose, so DeepCreator provides it across the same boundary: `@ryanyujazz/dsh-session-admin` (Host row `deepcreator-session-admin`) exposes one Typert Remote `delete` that validates the session id, locates the session directory under the shared sessions root (the official jsonl backend names each session directory by the raw id), refuses ambiguous matches and live sessions — the official write-behind would recreate the log — and destroys the directory. ui-workspace's session row menu offers 删除会话 after 归档会话 with destructive styling; a risk-confirmation dialog (acknowledgement checkbox) guards the action, and the client refreshes the official session list afterwards so the row disappears.

## Package boundaries

Each UI feature is one Cordis Client plugin. A feature may contain `contract`, `model-adapter`, `view-model`, and `view` directories when the code needs those distinctions; the directories do not create additional plugins. The model adapter reads official Runtime objects, the view model owns presentation-only stores and actions, and React views consume Slot-derived props. `apply.ts` is the only cross-domain assembly point.

`@ryanyujazz/dsh-client-compat` records the supported official package version and Git SHA and exports public types. Runtime object identity still comes directly from the official ModuleLoader table. `@ryanyujazz/dsh-client-ui-primitives` is an immediately available Client module whose Host apply is empty; it publishes shared React controls once and injects its global browser styles without owning business state. Its product icon set owns the locally bundled DeepSeeker CodeAgent folder Lottie used by Workspace, Conversation hero, Agent Preset and Artifact surfaces; the animation is lazy-loaded, theme-colored through `currentColor`, and reduced-motion aware, while consumers provide only presentation state such as open/closed.

ui-primitives also owns the DOM-free code-theme registry and pure Diff model. The model aligns each official hunk with jsdiff line and word passes, advances optional absolute old/new starts, and combines word marks with Shiki token spans without owning Tool or Repository state. ui-theme persists independent Light/Dark code-theme ids and one code-font id, publishes the active code appearance in ThemeRuntime, and ui-layout is the only presenter that stamps `body[data-code-theme]`. Named code themes own editor colors and translucent Diff line/word highlights; application chrome keeps ownership of line numbers, signs and controls. Write/Edit cards and Review consume the same rows and renderer, while retaining their own surrounding navigation and lifecycle; Review makes the shared hunk base transparent so its canvas follows the Workbench application's light/dark surface instead of the selected code-theme background.

`@ryanyujazz/dsh-client-ui-workbench` is the sole occupant of the retained root `details` seat. It owns only session-scoped browser presentation state: type Groups, same-type tabs, routes, explicit left-to-right column Tracks, per-column widths/cell ratios, outer width and manual Focus. The state is persisted under `dsh.deepcreator.workbench.session.v2.<sessionId>` and is pruned with Session scope death; `ui-layout` still owns rendered Stage geometry and reports both resolved Workbench width and Stage width to its occupant. The Controller retains the latest presentation command only as an observable snapshot; each newly mounted session Root initializes its sequence watermark from that snapshot and consumes only later commands, preventing the previous session's final panel action from replaying when a new project's first message activates its session scope. The v1 pair-axis/parked snapshot is intentionally retired.

The details column and Mosaic cells are frameless geometry owners. The Workbench root supplies a 2px inset, and every visible cell is rendered through ui-primitives' public `WorkbenchPanelShell`, whose rounded frame adds a 2px cell margin and owns the compact Header, common navigation/actions and Body boundary. All same-type instance tabs render through the public business-state-free `WorkbenchPanelTabs`: its pill tabs replace the redundant type title while instances are open, a Provider create action follows the newest tab, and each reserved close slot reveals its control on tab hover or direct keyboard focus without reflowing the label. File-backed Providers may pair tab labels with `tabFilePaths`; the shell then renders the shared Material `FileIcon`, while terminal and other non-file tabs stay icon-free. Header-scope Provider actions use the ordinary `contributeHeaderActions()` owner callback; the Workbench passes those nodes to the shell's `leftActions`/`rightActions` props, and only create-tab actions use the tabs' trailing target. Content-scope controls stay in Body: Activity's child status and conversation jump form an instance-local toolbar above its transcript instead of competing with tabs and Focus/visibility controls in the shared Header. Housing the state-free shell and tabs in ui-primitives and the contribution lifecycle in Workbench avoids cross-bundle React Context identity and runtime value imports between independently loaded Cordis Client plugins.

Opening is a deterministic topology transaction. One type uses its Provider-declared Stage ratio (Activity/Artifact/Terminal one third; Review/Browser one half, with Browser retaining the stable `browser` type id), the second splits that column vertically without changing its possibly user-adjusted width, the third creates two equal columns at one-half Stage, the fourth splits the second column, and the fifth creates three equal columns at two-thirds Stage. Every panel column has a 150px floor and Conversation has a 360px floor. Closing one cell lets its sibling fill the column; closing an empty column removes exactly that column while survivor pixel widths remain unchanged and right-aligned. Responsive concession derives a view by removing whole columns from right to left without rewriting topology. Activating a responsive-hidden type swaps its real cell with the real top-left cell; opening a type absent from topology when a new odd column cannot fit replaces the top-left type atomically. Panel types and their keyed body/icon renderers are registered independently, so a missing Provider leaves a disconnected Group rather than copying business state into the shell.

The Session Header ends in one stable More menu containing only conversation render modes and Session actions. Workbench owns a separate responsive control: all five type buttons render inline when the complete strip fits, otherwise the entire strip becomes one Panel launcher whose menu contains every type. This all-or-one switch is chrome-only projection and never changes Workbench topology or visibility. The official `dsh-session-log-export` controller and dialog remain mounted and authoritative, while ui-conversation relocates its existing trigger into the Session group instead of implementing another export path.

Activity subagent tabs are secondary occurrences of the official conversation surface, not a second transcript implementation. The patched `0.1.1-rc.2` Runtime exposes `sessions.provideInfoFor(sessionId)`, whose first subscriber retains a catalog-addressed child and opens the official 50-message tail without changing `list.current`; subscribers share one Session, open promise, assembler and stream, and the final non-current release cools live handling while retaining a bounded assembled presentation. Reopen still validates the official tail and skips reconstruction only when the event sequence is unchanged, avoiding the allocation/GC spike seen during repeated tab switches. The patched UI Renderer `SessionProvider` accepts that explicit id. ui-conversation publishes its already-authorized `conversation.session` renderer as a UI-only capability, and the Activity adapter invokes it under the explicit child scope with `transcriptOnly` and an occurrence `surfaceId`. A cold Activity occurrence mounts the same complete resident Turn window that the main conversation renders from the official initial tail, with no Activity-only one-Turn budget; its history affordance delegates directly to the same official `hasMore/loadOlder` pagination. Scroll state is per occurrence and image URLs are reference-counted. Only an active tab in a visible panel on a visible document holds the explicit lease, so inactive children receive no transcript assembly or React commits; jobs-admin no longer transports child event windows.

Ordinary composer submission uses a presentation-only local echo to cover the interval between optimistic draft clearing and the first official Session projection. InputHub places that echo in the conversation tail, QueueDock, or steering tail according to the already-resolved delivery mode, pairs it FIFO when matching authoritative queue or durable chat content arrives, and retires it only after the owning surface commits that successor. It is never persisted, replayed, or promoted into Session state; rejection withdraws it and retains the existing draft-restoration contract.

The former `ui-conversation` DetailsPanel, its `conversation.details.tool` slot, and `ui-tool`'s inert details registration are fully removed; a future inspector must return as a Workbench Provider. Activity reads official `jobsBySession` directly, and the DeepCreator bundle disables the official `ui-jobs` row to keep one entry point. Artifact, Review and Terminal surfaces never synthesize domain state while their Host Remote is absent. Review separates repository-scoped Git ranges from workspace-scoped Turn history. Git status uses porcelain v2 with POSIX public paths: ordinary untracked directories expand, nested repositories/submodules remain atomic drill-down rows, and an optional provider-defined `repository` location keeps each Git scope inside its selected repository. Turn manifest v2 recursively merges tracked and non-ignored files from every repository into a synthetic workspace tree, excludes `.git`, stores symlink targets without following them, and records owner repository plus repository-relative path for independent commit reconciliation; v1 manifests remain root-owned. A multi-repository Turn keeps history and cards but disables Undo, while a single owning repository retains the protected three-way Undo. `status` supplies the lightweight file list and `summary` supplies explicit presentation and line-stat states without loading sources, so binary and metadata-only changes never become fake zero counts. The conversation's mutation rows focus a file's change through the Workbench's generic reveal channel: `ctx.workbench.reveal(typeId, target)` publishes one presentation command carrying a provider-defined target, and the root delivers the latest target to the addressed panel's owner props as `reveal: { target, nonce }` (render-side only, never store-persisted); ui-conversation reads the optional service through `ctx.get` with a type-only contract dependency and falls back to the host open when no Workbench or review type is composed. Its general file opener is a separate Artifact-first route shared by Read rows, produced-file chips and resolved closing-prose mentions: after cwd resolution it calls `workbench.activate('artifact', path)`, whose instance id is the canonical tab identity, and uses the official Host opener only when Artifact is not composed. The Review body is a session-owned viewport data plane: its controller starts before panel open, keeps metadata/history current while hidden, then visible Review preheats six non-atomic bodies and queues focus/near-viewport/idle requests at concurrency one. Repository drill-down stays in that panel and restores cached scope, expansion and scroll state through its breadcrumb. The prepared scroll range initially exposes those six files; a boundary sentinel queues an off-DOM two-screen batch, then mounts its heavy bodies invisibly one per frame, and extends the range only after both wire data and body residency settle. A direct reveal recenters the range on its target and creates independent before/after sentinels with the same behavior. Files remain logically expanded, while resident heavy bodies unload far away behind width-bucketed measured placeholders; resident/focused bodies are exempt from a 16-body soft limit. File entries, totals, metadata and history expose separate subscriptions, unchanged history polls publish nothing, and raw source/patch plus Shiki token caches each use a weighted memory budget. Omitted unchanged source context stays as a range until its FoldRow opens, and controlled fold keys survive body residency changes. Status refreshes still preserve unchanged file identity, settled mutation tools still invalidate through the same queue, and background checks keep their existing manual/turn-end policy. `@ryanyujazz/dsh-skills` bundles the eleven official deepseek-harness development skills verbatim under `assets/skills/` and registers them through the official `ctx.skills` registry as one immutable `bundled`-source provider (`deepcreator-skills` row) — frontmatter parsed with the official filesystem semantics, bodies served with the packaged directory as the resource base, `BUNDLED_SKILL_RANK` so user-owned definitions win, and disabling the row is the opt-out.

The current Review data plane supersedes the prepared-frontier and periodic-history-poll description above. Successful public `tools/result` write/edit events feed a disposable per-Turn tracker, including `rootCallId` attribution for nested Code Mode calls; discontinuity or unknown filesystem writes become dirty and coalesce into one authoritative snapshot, while turn end still persists the existing private ref used by history, commit reconciliation and Undo. `manifest` creates an opaque generation and returns its porcelain file seed while authoritative tree/history/stat work remains lazy; `patches` computes foreground pathspec batches for focus/viewport demand and shares each result by generation. Only sustained demand across several batches enables an idle-debounced fill of the remaining aggregate patch map, so opening one screen never starts a whole-repository patch prefetch. An exact current-Turn edit combines the tracker `after` text with one baseline object instead of awaiting a worktree snapshot. `source` lazily loads an old/new side through a shared `cat-file --batch`, and `probe` compares only an in-memory watcher epoch. The client falls back to legacy RPCs for compatibility, but otherwise warms precise mutation paths from official events, performs zero hidden-panel polling, rejects late generation/request ownership/sequence results, and virtualizes file sections with repository/scope-qualified path keys, conservative estimates and dynamic measurement. Expansion and repository/scope transitions reset estimates before paint and synchronously remeasure only the mounted viewport, so a cached nested-repository body cannot retain the compact estimate and overlap later absolute rows. Initial responses contain hunks only; unified parsing runs in a session controller-owned Worker, mounted hunks paint plain text first and enter a cancellable idle highlight queue, and complete source enters the client only after an omitted-context FoldRow is opened. The 500/2000-file fixtures keep DOM residency and patch request volume viewport-bounded.

Artifacts follow the official produced-files fact instead of a DeepCreator-owned vocabulary. The panel's list projects the same session events the official `ui-deliverables` plugin renders at the turn tail: a per-turn context starts at `turn/start`, records each `tool/call` view, and an append-surface `tool/result` collects the paths a diff card (or generic `edit` card) produced — reads, deletes, failed results and replacement surfaces contribute nothing. The `artifacts` snapshot builder folds the turns into one record per path (latest production wins, newest first), so the panel lists exactly what the conversation lists. `@ryanyujazz/dsh-client-ui-workbench-artifact` owns the `artifact` panel type (id and persisted fields unchanged, so no workbench v2 migration) and the type entry icon: a blue dot in its top-right corner signals produced files the user has not looked at yet, advancing a per-session seen watermark only while the panel group is visible (hidden groups stay mounted and keep the dot). Instance content reads through the mounted `artifacts` remote namespace — a Host reader that canonicalizes and fences the path to the session workspace — keyed by path so unchanged paths do not re-read; the instance view keeps that full path as a presentation-only breadcrumb above every loading, error, and content state. Its fixed trailing folder action derives the containing directory and delegates native opening to the official `ctx.workspaces.openPath` boundary; Markdown/MDX places a per-file icon-only `Preview | Code` presentation control immediately before that action (supplied eye and product `</>` glyphs, with localized hover/focus hints), with preview reusing the shared settled-conversation `MarkdownText` pipeline and code retaining the registered `CodeSurface` renderer. The preview document shares the theme-owned 748px `--dsh-reading-content-width` measure with Conversation and centers inside a panel-wide scroll surface, so narrow panels shrink while the scrollbar remains at the panel edge. Artifact adds no Electron-private filesystem channel. `ui-workbench-tools` retains Review and Terminal only; Browser presentation is composed independently.

Workbench Terminal is a local-Host interactive PTY without moving authority into the browser. `terminal-workbench` registers an additive `system` Backend with the official `ctx.terminals` registry, so the registry still mints ids, fences every operation to the exact Agent and closes sessions on Agent/Host teardown. The Backend owns `node-pty`/ConPTY, platform Shell selection, bounded raw ANSI cursor reads, ordered input and resize. Windows resolves PowerShell before cmd; macOS/Linux prefer the user's login Shell. The Remote forces each new system terminal's initial cwd to the ordinary Session workspace root. On first Client initialization with no open tabs, the Provider restores one running terminal for that Session or spawns one system terminal and opens it; a per-Session guard prevents closing the last tab from causing a replacement loop. Terminal has no management Home route or header-level signal/kill actions; when no tab remains, the Body is a plain empty state. Removing a Terminal tab immediately kills its owned PTY without confirmation, while hiding the Terminal Group retains both tabs and processes. The Client embeds xterm and Fit; it receives no Node, filesystem or generic IPC capability. The official line-oriented Bash Backend stays mounted for model/tool consumers and is not used as the default Workbench renderer.

Review has three Git ranges—unstaged (`index → worktree`), staged (`HEAD → index`), uncommitted (`HEAD → worktree`)—plus current and retained Turn ranges (`turn start tree → live/end tree`). The Host captures Turn snapshots with a temporary index at official Agent/Session boundaries. Git workspaces anchor unresolved trees under private `refs/deepcreator/turns/...` synthetic commits; non-Git workspaces use an isolated bare object database under DSH home, never mutate the project with a `.git`, and expose only current/history Turn scopes. Per-file HEAD reconciliation drives Git partial-commit state; fully committed refs are deleted and omitted from history immediately, including when the commit occurs before the Turn ends. The only Review mutation is protected Git undo for the newest unresolved completed Turn. The session `ReviewCacheController` is shared by the panel and conversation change cards, defaults filesystem workspaces to their newest Turn, and treats absent metadata as unknown rather than resolved so mutation links remain Review-first. Provider-defined Workbench presentation parameters carry Turn scope without encoding it into file paths. The official `ui-deliverables` row remains composed for its Turn facts, closing-prose vocabulary and model guidance. Artifact contributes a higher-priority renderer to that official selector chain, presenting only the addressed Turn's produced files in the shared file-card chrome; ui-conversation then renders the Review-owned `deepcreator.conversation.chat.turnChanges` list immediately below it. Review keeps binary paths in repository truth for reconciliation and Undo, but its conversation card omits `presentation: "binary"`, so images and document outputs are classified only as artifacts in the chat flow.

## Composition

The `deepcreator` profile composes `dsh-base`, `dsh-web-app`, retained third-party bundles, and `dsh-deepcreator-web` in that order. The DeepCreator bundle disables replaced official UI rows and inserts custom rows under `deepcreator-*` ids. The development migrator links those bare plugin packages directly into the profile because a local `link:` bundle does not install its workspace dependencies. Shared extension points retain official Slot names. Product-only child slots use the `deepcreator.*` namespace. Layout therefore declares `deepcreator.shell.sidebar-toggle` as the stable frame-chrome seat for ui-sidebar's reopen control: closing the sidebar resolves its track to zero, while the seat remains at one coordinate across the root-scoped Hero and session-scoped conversation states. Official Client inject metadata remains descriptive; unchanged official plugins continue to register against the retained Slot services and were verified in the assembled browser.

The official `ui-settings` row is retained as the sole owner of `settingsScope`, `settingsSchema`, and the shared settings describe mirror. DeepCreator's `@ryanyujazz/dsh-client-ui-settings` is only an extension contract: it declares `deepcreator.settings.preferences.item`, which the custom settings shell places inside `settings.general.item`. Theme and conversation plugins register their durable preference rows into that child Slot and consume the official service face. This keeps newly added official settings packages loadable because they still inject the official module id. The settings namespace `ui-conversation`, fields `busyEnter` and `defaultRenderMode`, render ids `normal | classic | think`, and default `classic` remain stable.

Conversation owns message and composer state but not attachment presentation. It declares `conversation.input.attachments` and `conversation.message.images`; the retained official attachment plugin fills both seats. The custom conversation tree supplies stable owner props and image-loading capability at those boundaries, so an official attachment component rewrite does not become a DeepCreator conversation migration.

Image generation is split across `@ryanyujazz/dsh-image-generation` and `@ryanyujazz/dsh-client-ui-image-generation`. The Host package registers the official `image-generation` Settings namespace, resolves write-only credential references per operation, and contributes one root-Agent `create_image` tool backed by native OpenAI Images, Seedream Ark, and Gemini image endpoints. Provider requests and result downloads honor the Host process's standard HTTP proxy environment without persisting proxy credentials in plugin settings. A successful call writes one fenced workspace PNG and one official durable image attachment. The Client package contributes its keyed plugin-settings card and tool row, then projects successful `create_image` result blocks through the additive `deepcreator.conversation.chat.turnMedia` list. The completed-turn order is closing Assistant prose, generated media, the official Artifact selector-chain winner, Review changes, and message actions; binary workspace output remains an Artifact fact rather than a source-diff row.

Optional feature Bundles compose through neutral seams instead of importing feature internals. Sidebar declares the empty `deepcreator.sidebar.primary.action` list, generated-image media declares `deepcreator.image-generation.result.action`, and the Host image package publishes `imageGenerationRuntime` for reversible request middleware and result observers. Structured image inputs carry provider-neutral semantic roles while legacy attachment/path arrays normalize to `generic`; with no optional registrants, these seams preserve existing rendering and generation behavior.

## Desktop process boundary

Electron owns one sandboxed BrowserWindow and one system-Node `dsh --profile deepcreator --port 0` child. The renderer accepts only the exact loopback origin reported after Loader settlement. External HTTP(S) links open through the operating system. On macOS, Electron hides the native title bar and positions the real traffic lights with their center on the conversation header's y=24 baseline; the sandboxed layout identifies that shell from Electron's default user agent and exposes one presentation marker, without a preload bridge or duplicated window state. The frame, sidebar, conversation, and details surfaces consume that marker to turn visible header whitespace (including the headerless hero's top 48px) into native drag regions while returning every real control to `no-drag`. On Windows, Electron also hides the native title bar but keeps the native caption buttons through the Window Controls Overlay at 32px; ui-layout detects that shell from the same user agent and draws a themed 32px title strip (base palette background, mirrored window title, whole-strip drag surface) above the three columns, positioned as the top-most web layer so columns, focused stages, drag handles, and portaled overlays all yield below it, while the theme presenter resolves the active palette's base background and primary label colors and pushes them through the `deepcreatorWindow.setTitleBarTheme` preload bridge after every theme change so the native buttons follow the in-app light/dark setting. Linux retains the native frame. Their renderer content adds no secondary drag region and still uses the zero-width close and fixed reopen seat, with platform-specific horizontal safe areas owned by CSS. Shutdown sends SIGTERM, waits for process and stdio closure, then escalates to SIGKILL after the configured timeout. The private Electron data directory is distinct from earlier local applications that used the same visible DeepCreator name.

Browser Use is a Host capability with optional presentation, not a Workbench feature. `BrowserRuntime` owns Provider selection, logical tab ids, turn leases, snapshot refs and live-state revisions; root Agents receive six semantic Browser ToolDefinitions, while Browser live state remains outside Session Projection. The separate `@ryanyujazz/dsh-presentation` package owns `open_in_deepcreator`, extensible resource resolvers, client capability claims, deadlines and fenced receipts, so Artifact or Review deployments need no Browser Runtime. `@ryanyujazz/dsh-client-presentation` owns the React-free Presenter registry and claim loop; Browser, Artifact and Review UI packages contribute adapters independently. Explicit user controls call its `open(input)` method, which crosses a Presentation Remote and rejoins the same resolver/claim/receipt flow under a synthetic user turn instead of calling Browser or Workbench internals. Hiding a Browser Group remains presentation-only, while closing one Browser instance crosses an agent-fenced Remote to close the exact Provider page and invalidate its logical tab. Snapshot bytes stay in Host artifacts and hydrate through a separate preview Remote whose loading/failure/retry state is Client-owned. Replacing the current Browser right panel with a floating window therefore changes only a Presenter and optional Surface host.

Desktop IAB is the narrow preload exception. Electron Main owns a persistent isolated partition and every `WebContentsView`; Host automation reaches Main only over an owner-only Unix socket or Windows named pipe authenticated by a random process token. The sandboxed app renderer receives only `mountSurface`, `setBounds`, `setVisible` and `unmountSurface`, so it cannot create or navigate pages, read DOM, send debugger commands or access files. User page input interrupts the exact Agent control lease; hiding a panel unmounts only its Surface. At Desktop startup, Electron also resolves the operating system proxy/PAC route for external Provider traffic and projects it into the official Host's standard proxy environment only when the deployment has not supplied an explicit route; no proxy credential crosses into plugin settings or the renderer. Managed Playwright runs in an independent DSH-owned process with isolated/persistent Profiles. System Chrome connects through a fixed-ID extension and explicit Native Messaging host and exposes only explicitly shared user tabs. None opens a remote-debugging port or shares authentication state across Providers.

## Upstream updates

An official update changes the version and SHA in `packages/client/compat/compatibility.json`, updates package dependencies, and runs `pnpm run verify:harness`, typechecking, bundle builds, tests, a `dump-config` comparison, and isolated browser/Desktop smoke tests. Compatibility failures are fixed at a declared slot, service, or compatibility boundary; feature packages must not recover a removed official implementation import with a silent fallback. The neighboring official source checkout remains untouched. Version-scoped `pnpm.patchedDependencies` patches remain explicit and mechanically rebased: Runtime/UI Renderer/UI Slots/Test Runtime carry the secondary-session capability, while Tool FS/Tools preserve optional `oldStart`/`newStart` diff metadata. The verifier executes the patched contracts, rejects dependencies on retired official packages, checks single-owner composition rows, and fails when an official upgrade drops a boundary.
