# DeepCreator architecture

DeepCreator is a presentation distribution over the official DeepSeek Harness runtime. The official process owns Agent execution, Session persistence, RPC, Settings, Workspace data, Client Runtime objects, and Slot rendering. DeepCreator owns Electron and the UI plugin rows listed by `@ryanyujazz/dsh-deepcreator-web`.

Session pinning remains presentation state in ui-workspace's persisted browser view store; it moves a Session row into a sibling pinned region without mutating official Workspace membership or Session persistence. Native folder opening stays on the official boundary: ui-workspace observes `connection.hostDescription.canOpenPath` and calls `ctx.workspaces.openPath`, whose Host implementation delegates to Finder, Explorer, or `xdg-open`; DeepCreator adds no Electron-private path-opening channel.

Session deletion is the one lifecycle verb the official harness does not expose, so DeepCreator provides it across the same boundary: `@ryanyujazz/dsh-session-admin` (Host row `deepcreator-session-admin`) exposes one Typert Remote `delete` that validates the session id, locates the session directory under the shared sessions root (the official jsonl backend names each session directory by the raw id), refuses ambiguous matches and live sessions — the official write-behind would recreate the log — and destroys the directory. ui-workspace's session row menu offers 删除会话 after 归档会话 with destructive styling; a risk-confirmation dialog (acknowledgement checkbox) guards the action, and the client refreshes the official session list afterwards so the row disappears.

## Package boundaries

Each UI feature is one Cordis Client plugin. A feature may contain `contract`, `model-adapter`, `view-model`, and `view` directories when the code needs those distinctions; the directories do not create additional plugins. The model adapter reads official Runtime objects, the view model owns presentation-only stores and actions, and React views consume Slot-derived props. `apply.ts` is the only cross-domain assembly point.

`@ryanyujazz/dsh-client-compat` records the supported official package version and Git SHA and exports public types. Runtime object identity still comes directly from the official ModuleLoader table. `@ryanyujazz/dsh-client-ui-primitives` is an immediately available Client module whose Host apply is empty; it publishes shared React controls once and injects its global browser styles without owning business state.

ui-primitives also owns the DOM-free code-theme registry and pure Diff model. The model aligns each official hunk with jsdiff line and word passes, advances optional absolute old/new starts, and combines word marks with Shiki token spans without owning Tool or Repository state. ui-theme persists independent Light/Dark code-theme ids and one code-font id, publishes the active code appearance in ThemeRuntime, and ui-layout is the only presenter that stamps `body[data-code-theme]`. Named code themes own editor colors and translucent Diff line/word highlights; application chrome keeps ownership of line numbers, signs and controls. Write/Edit cards and Review consume the same rows and renderer, while retaining their own surrounding navigation and lifecycle; Review makes the shared hunk base transparent so its canvas follows the Workbench application's light/dark surface instead of the selected code-theme background.

`@ryanyujazz/dsh-client-ui-workbench` is the sole occupant of the retained root `details` seat. It owns only session-scoped browser presentation state: type Groups, same-type tabs, routes, explicit left-to-right column Tracks, per-column widths/cell ratios, outer width and manual Focus. The state is persisted under `dsh.deepcreator.workbench.session.v2.<sessionId>` and is pruned with Session scope death; `ui-layout` still owns rendered Stage geometry and reports both resolved Workbench width and Stage width to its occupant. The Controller retains the latest presentation command only as an observable snapshot; each newly mounted session Root initializes its sequence watermark from that snapshot and consumes only later commands, preventing the previous session's final panel action from replaying when a new project's first message activates its session scope. The v1 pair-axis/parked snapshot is intentionally retired.

The details column and Mosaic cells are frameless geometry owners. The Workbench root supplies a 2px inset, and every visible cell is rendered through ui-primitives' public `WorkbenchPanelShell`, whose rounded frame adds a 2px cell margin and owns the compact Header, common navigation/actions and Body boundary. All same-type instance tabs render through the public business-state-free `WorkbenchPanelTabs`: its pill tabs replace the redundant type title while instances are open, a Provider create action follows the newest tab, and each reserved close slot reveals its control on tab hover or direct keyboard focus without reflowing the label. File-backed Providers may pair tab labels with `tabFilePaths`; the shell then renders the shared Material `FileIcon`, while terminal and other non-file tabs stay icon-free. Providers render Body content and contribute action nodes through the ordinary `contributeHeaderActions()` owner callback rather than creating a second toolbar. The Workbench passes those nodes to the shell's `leftActions`/`rightActions` props; only create-tab actions use the tabs' trailing target, while all other Provider actions share the right group with Home/back, Focus and visibility controls. Housing the state-free shell and tabs in ui-primitives and the contribution lifecycle in Workbench avoids cross-bundle React Context identity and runtime value imports between independently loaded Cordis Client plugins.

Opening is a deterministic topology transaction. One type uses its Provider-declared Stage ratio (Activity/Artifact/Terminal one third; Review/Preview one half, with Preview retaining the stable `browser` type id), the second splits that column vertically without changing its possibly user-adjusted width, the third creates two equal columns at one-half Stage, the fourth splits the second column, and the fifth creates three equal columns at two-thirds Stage. Every panel column has a 150px floor and Conversation has a 360px floor. Closing one cell lets its sibling fill the column; closing an empty column removes exactly that column while survivor pixel widths remain unchanged and right-aligned. Responsive concession derives a view by removing whole columns from right to left without rewriting topology. Activating a responsive-hidden type swaps its real cell with the real top-left cell; opening a type absent from topology when a new odd column cannot fit replaces the top-left type atomically. Panel types and their keyed body/icon renderers are registered independently, so a missing Provider leaves a disconnected Group rather than copying business state into the shell.

The Session Header ends in one stable More menu containing only conversation render modes and Session actions. Workbench owns a separate responsive control: all five type buttons render inline when the complete strip fits, otherwise the entire strip becomes one Panel launcher whose menu contains every type. This all-or-one switch is chrome-only projection and never changes Workbench topology or visibility. The official `dsh-session-log-export` controller and dialog remain mounted and authoritative, while ui-conversation relocates its existing trigger into the Session group instead of implementing another export path.

The former `ui-conversation` DetailsPanel, its `conversation.details.tool` slot, and `ui-tool`'s inert details registration are fully removed; a future inspector must return as a Workbench Provider. Activity reads official `jobsBySession` directly, and the DeepCreator bundle disables the official `ui-jobs` row to keep one entry point. Artifact, Review and Terminal surfaces never synthesize domain state while their Host Remote is absent. Review's Host service returns explicit staged (`HEAD → index`) and working-tree (`index → worktree`) layers with source snapshots, rename/copy paths and binary state; the Client derives accurate hunk line starts from unified headers and remains read-only. The conversation's mutation rows focus a file's change through the Workbench's generic reveal channel: `ctx.workbench.reveal(typeId, target)` publishes one presentation command carrying a provider-defined target, and the root delivers the latest target to the addressed panel's owner props as `reveal: { target, nonce }` (render-side only, never store-persisted); ui-conversation reads the optional service through `ctx.get` with a type-only contract dependency and falls back to the host open when no Workbench or review type is composed. Its general file opener is a separate Artifact-first route shared by Read rows, produced-file chips and resolved closing-prose mentions: after cwd resolution it calls `workbench.activate('artifact', path)`, whose instance id is the canonical tab identity, and uses the official Host opener only when Artifact is not composed. The Review body is a session-owned warm data plane: one controller per session starts when the session becomes current (before any panel opens) and subscribes to the session snapshot feed directly — the panel is a `useSyncExternalStore` view. Entry fetches status then prefetches every file's diff sequentially (capped); diffs parse once (hunks merged with source snapshots, referentially stable through re-renders); status refreshes merge per file instead of rebuilding (identity, caches and expansion survive; moved XY/rename carries the cache forward stale); expansion is remembered per repository in localStorage and restored across mounts; ready caches evict oldest beyond a safety cap; settled edit/write/bash results invalidate in the background (debounced; a single edit targets its file) and revalidate through the same sequential queue, and the hidden→visible owner transition is the catch-all refresh — background refreshes stay silent and reserve `git diff --check` for manual refreshes and turn ends. `@ryanyujazz/dsh-skills` bundles the eleven official deepseek-harness development skills verbatim under `assets/skills/` and registers them through the official `ctx.skills` registry as one immutable `bundled`-source provider (`deepcreator-skills` row) — frontmatter parsed with the official filesystem semantics, bodies served with the packaged directory as the resource base, `BUNDLED_SKILL_RANK` so user-owned definitions win, and disabling the row is the opt-out.

Artifacts follow the official produced-files fact instead of a DeepCreator-owned vocabulary. The panel's list projects the same session events the official `ui-deliverables` plugin renders at the turn tail: a per-turn context starts at `turn/start`, records each `tool/call` view, and an append-surface `tool/result` collects the paths a diff card (or generic `edit` card) produced — reads, deletes, failed results and replacement surfaces contribute nothing. The `artifacts` snapshot builder folds the turns into one record per path (latest production wins, newest first), so the panel lists exactly what the conversation lists. `@ryanyujazz/dsh-client-ui-workbench-artifact` owns the `artifact` panel type (id and persisted fields unchanged, so no workbench v2 migration) and the type entry icon: a blue dot in its top-right corner signals produced files the user has not looked at yet, advancing a per-session seen watermark only while the panel group is visible (hidden groups stay mounted and keep the dot). Instance content reads through the mounted `artifacts` remote namespace — a Host reader that canonicalizes and fences the path to the session workspace — keyed by path so unchanged paths do not re-read; the instance view keeps that full path as a presentation-only breadcrumb above every loading, error, and content state. Its fixed trailing folder action derives the containing directory and delegates native opening to the official `ctx.workspaces.openPath` boundary; Artifact adds no renderer or Electron-private filesystem channel. `ui-workbench-tools` retains Review, Terminal and Preview only.

Workbench Terminal is a local-Host interactive PTY without moving authority into the browser. `terminal-workbench` registers an additive `system` Backend with the official `ctx.terminals` registry, so the registry still mints ids, fences every operation to the exact Agent and closes sessions on Agent/Host teardown. The Backend owns `node-pty`/ConPTY, platform Shell selection, bounded raw ANSI cursor reads, ordered input and resize. Windows resolves PowerShell before cmd; macOS/Linux prefer the user's login Shell. The Remote forces each new system terminal's initial cwd to the ordinary Session workspace root. On first Client initialization with no open tabs, the Provider restores one running terminal for that Session or spawns one system terminal and opens it; a per-Session guard prevents closing the last tab from causing a replacement loop. Terminal has no management Home route or header-level signal/kill actions; when no tab remains, the Body is a plain empty state. Removing a Terminal tab immediately kills its owned PTY without confirmation, while hiding the Terminal Group retains both tabs and processes. The Client embeds xterm and Fit; it receives no Node, filesystem or generic IPC capability. The official line-oriented Bash Backend stays mounted for model/tool consumers and is not used as the default Workbench renderer.

## Composition

The `deepcreator` profile composes `dsh-base`, `dsh-web-app`, retained third-party bundles, and `dsh-deepcreator-web` in that order. The DeepCreator bundle disables replaced official UI rows and inserts custom rows under `deepcreator-*` ids. The development migrator links those bare plugin packages directly into the profile because a local `link:` bundle does not install its workspace dependencies. Shared extension points retain official Slot names. Product-only child slots use the `deepcreator.*` namespace. Layout therefore declares `deepcreator.shell.sidebar-toggle` as the stable frame-chrome seat for ui-sidebar's reopen control: closing the sidebar resolves its track to zero, while the seat remains at one coordinate across the root-scoped Hero and session-scoped conversation states. Official Client inject metadata remains descriptive; unchanged official plugins continue to register against the retained Slot services and were verified in the assembled browser.

The settings shell registers the Preferences block into `settings.general.item` and declares `deepcreator.settings.preferences.item`. Theme and conversation plugins register their durable preference rows into that child Slot. The settings namespace `ui-conversation`, fields `busyEnter` and `defaultRenderMode`, render ids `normal | classic | think`, and default `classic` remain stable.

## Desktop process boundary

Electron owns one sandboxed BrowserWindow and one system-Node `dsh --profile deepcreator --port 0` child. The renderer accepts only the exact loopback origin reported after Loader settlement. External HTTP(S) links open through the operating system. On macOS, Electron hides the native title bar and positions the real traffic lights with their center on the conversation header's y=24 baseline; the sandboxed layout identifies that shell from Electron's default user agent and exposes one presentation marker, without a preload bridge or duplicated window state. The frame, sidebar, conversation, and details surfaces consume that marker to turn visible header whitespace (including the headerless hero's top 48px) into native drag regions while returning every real control to `no-drag`. Windows and Linux retain their native frame and system window controls; their renderer content adds no secondary drag region and still uses the zero-width close and fixed reopen seat, with platform-specific horizontal safe areas owned by CSS. Shutdown sends SIGTERM, waits for process and stdio closure, then escalates to SIGKILL after the configured timeout. The private Electron data directory is distinct from earlier local applications that used the same visible DeepCreator name.

Browser Panels are the reviewed exception to the former no-preload rule. The main renderer receives one frozen, narrowly typed `deepcreatorBrowser` bridge exposing only create, navigate, back, forward, reload, setBounds, close and state/popup subscriptions. Browser content runs in `WebContentsView` with sandbox, context isolation and web security enabled, Node disabled, and a non-persistent partition. Only HTTP(S) navigation is accepted; downloads and non-HTTP(S) popups are rejected, while HTTP(S) popups are returned to the renderer as a new Browser tab request. Browser views never enter DSH Host or Session state and are destroyed on tab/session/window teardown.

## Upstream updates

An official update changes the version and SHA in `packages/client/compat/compatibility.json`, updates package dependencies, and runs `pnpm run verify:harness`, typechecking, bundle builds, tests, a `dump-config` comparison, and visual regression. Compatibility failures are fixed in `compat` or the affected feature plugin. The neighboring official source checkout remains untouched; version-scoped `pnpm.patchedDependencies` patches only the installed package that exports FileDiff and computes Write/Edit hunks, preserving optional `oldStart`/`newStart` metadata that the upstream implementation already calculates. The verifier executes that patched computation and fails if an official upgrade drops the contract. Removed APIs receive no silent fallback.
