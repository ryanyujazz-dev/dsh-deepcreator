# DeepCreator Review Service

Scoped Review and per-turn change history for Workbench. In Git workspaces the default `uncommitted` scope is `HEAD → worktree`; before a repository has its first commit, Git's empty tree replaces `HEAD`. `unstaged` (`index → worktree`), `staged` (`HEAD → index`), and `{ turn }` (turn start → live/end snapshot) are also available. A non-Git workspace exposes current and completed Turn scopes only. The generation protocol returns source-free unified patches first and loads one file side only when omitted context is opened; the legacy `diff` RPC still supplies full snapshots for old clients.

`status(session, scope, location?)` returns the file list without loading source snapshots. Git scopes stop at the selected repository boundary: ordinary untracked directories expand to files, while nested repositories and submodules are atomic drill-down entries. `location.repository` is always workspace-relative POSIX syntax, including on Windows. The backward-compatible `summary(session, scope, location?)` computes range-wide `--numstat` once and reports explicit entry/presentation/line-stat states, so binary, empty, rename-only, mode-only and repository changes never masquerade as `+0 -0`. Older clients and Hosts may continue using `diff` alone.

`manifest(session, scope, location?)` creates an opaque generation and returns its branch and file identities as soon as the porcelain seed is ready; history and line statistics may be marked pending while one shared authoritative snapshot remains lazy. `patches(session, generation, paths[])` computes only the requested viewport paths on the foreground path and caches them by generation; only sustained demand across several batches enables an idle-debounced fill of the remaining aggregate patch map. Exact current-Turn edits read their tracked `after` text directly and need only the baseline object; they do not wait for a worktree snapshot. `source(...)` lazily reads one old/new side through a shared `git cat-file --batch`, and visible clients use the in-memory-only `probe(session, knownEpoch)` to detect external edits without running Git. The compatibility `history/status/summary/diff` methods remain available and adapt to the same data plane where possible.

Successful public `tools/result` events for `write` and `edit` feed a disposable Turn tracker. It associates nested Code Mode calls through `rootCallId`, coalesces each path to its first `before` and latest `after`, and drops content restored to its starting value. Discontinuous or unknown writes, shell commands and restarted open Turns mark the preview dirty and coalesce into one authoritative snapshot. Turn end always writes the existing private Git ref and that durable result remains the source of truth for history, commit reconciliation and Undo; the tracker never becomes a second persisted business state.

Turn boundaries use a v2 workspace snapshot rather than the current Git boundary. Each repository contributes tracked and non-ignored untracked files; nested repositories are recursively merged, `.git` metadata is excluded, symlinks store only their target string, and each manifest file records its owning repository and repository-relative path. v1 manifests remain readable as root-repository records. Commit reconciliation runs independently per owning repository, so a root commit cannot clear a child-repository file (and vice versa).

Worktree snapshots are captured at official turn boundaries: start before the first `agent/pre-step`, end at awaited `agent/turn-stopping`, with `turn/end` as fallback. A temporary index writes Git trees without touching the real branch, index, or worktree. Open turns compare the retained start tree with the live worktree, so mutation links can reveal a Diff before the turn ends. Git workspaces anchor synthetic commits under `refs/deepcreator/turns/{sessionId}/{turn}`; non-Git workspaces use a session-private bare object database under DSH home, exclude that private state if the workspace contains it, and never create a project `.git`. Commit reconciliation remains Git-only, conservative, and per file; a fully committed turn is removed immediately, while non-Git completed turns remain available as history.

`undoTurn` is the only mutation. It accepts only the newest unresolved turn, computes reverse three-way candidates for both index and worktree in temporary Git trees, rechecks HEAD/index/worktree for races, and only then applies the prepared result. Single-repository Turns remain undoable even when that repository is nested. Cross-repository Turns retain history and per-repository commit detection but intentionally disable undo. Conflicts and stale state reject the whole operation, preserving later manual edits and preventing partial undo. No stage, unstage, or commit UI is provided.
