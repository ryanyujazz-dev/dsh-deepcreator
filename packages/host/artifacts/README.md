# DeepCreator Artifact Reader

Host-owned workspace artifact reader and HTML preview materializer for the Workbench Artifact panel. The panel's list is a Client-side session-event projection of the official deliverables mechanism (files the model wrote or edited). The Typert Remote `read` resolves an absolute or workspace-relative path, canonicalizes it, fences it to the Session workspace, and returns a tagged payload: UTF-8 text, a fenced image/PDF loopback URL, Mammoth-converted DOCX HTML, or `word-extractor` legacy-DOC text. The separate `preview` Remote accepts only `.html`/`.htm` entries and returns a loopback HTTP URL suitable for Browser Runtime. Each preview origin serves only the entry's directory, rejects hidden paths, symlink escape and non-web resource types, binds to `127.0.0.1`, and dies with the Host plugin. Escaping paths, missing files and sessions without a workspace fail with explicit error codes; no produced-file business state lives here.

The Host also contributes one stable Agent prompt section and the `artifact` resource description used by `open_in_deepcreator`. The prompt asks the Agent to distinguish disposable observations from user-consumable results, retain requested or valuable non-project outputs under the workspace `output/` tree, verify their returned paths, and avoid persisting every intermediate screenshot, trace, or temporary file. This is soft semantic guidance rather than a second deliverable state machine; official tool render intents and Session events remain authoritative. Artifact presentation accepts `{ kind: "artifact", workspacePath }`, where `workspacePath` is the verified absolute or workspace-relative path of an existing file. The old `artifactId` property is rejected by the exact schema, while attachment ids, content hashes and URLs are rejected by resolver parsing. Presentation materialization resolves relative and absolute paths to one workspace-rooted instance identity, so Markdown/text/code, PNG/JPG and other supported images, PDF, DOC/DOCX, HTML and other readable workspace outputs continue through their existing renderers. After creating and verifying a primary user-consumable artifact, the root Agent presents that one output proactively. A screenshot image block already delivers its Session attachment; it is opened as an Artifact only when a workspace output exists, using the returned `outputPath` as `workspacePath`. Ordinary source, test, configuration, dependency, temporary, and secondary implementation files remain in the produced-files list instead of opening panels. Explicit user intent and current-turn dismissal always win.
