# DeepCreator Artifact Reader

Workbench 产物面板的 Host 侧工作区文件读取与 HTML 预览物化服务。面板列表是官方 deliverables 机制的客户端会话事件投影（模型写入或编辑的文件）。Typert Remote `read` 解析绝对或相对工作区路径、规范化并限制在 Session 工作区内，并返回带类型的载荷：UTF-8 文本、受围栏保护的图片／PDF loopback URL、Mammoth 转换的 DOCX HTML，或由 `word-extractor` 提取的旧 DOC 正文；同源图片／PDF capability 端点支持 `HEAD` 和单段 byte-range 响应，使 Chromium 内嵌 PDF 查看器可以正常 seek，而不必退化为整文件下载。独立的 `preview` Remote 只接受 `.html`／`.htm` 入口并返回可交给 Browser Runtime 的 loopback HTTP URL。每个预览 Origin 只服务入口文件所在目录，拒绝隐藏路径、符号链接逃逸及非 Web 资源类型，只绑定 `127.0.0.1` 并随 Host 插件销毁。逃逸路径、缺失文件与无工作区会话以显式错误码失败；此处不持有产物业务状态。

Host 同时贡献一段稳定的 Agent 系统提示，以及 `open_in_deepcreator` 使用的 `artifact` 资源描述。提示引导 Agent 区分一次性内部观察与用户可消费成果：用户请求或值得保留的非项目产物进入工作区 `output/`，结束前验证真实返回路径，同时避免把每张中间截图、trace 或临时文件持久化。这只是软语义指引，不建立第二套成果状态机；官方工具呈现意图和 Session 事件仍是权威事实。Artifact 呈现只接受 `{ kind: "artifact", workspacePath }`，其中 `workspacePath` 必须是已存在文件的已验证工作区相对路径或绝对路径；旧 `artifactId` 属性由精确 Schema 拒绝，Attachment ID、内容哈希和 URL 则由 resolver 解析明确拒绝。物化会把相对与绝对路径归一为同一个工作区身份：HTML／HTM 入口先转换为受围栏保护的 loopback URL，再由 Browser Runtime 物化为 IAB `browser-tab`；Markdown／文本／代码、PNG／JPG 等受支持图片、PDF、DOC／DOCX 等其他可读取产物仍进入 Artifact 面板。截图的 image block 已经交付 Session 附件；只有存在工作区输出文件时才额外打开 Artifact，并把截图返回的 `outputPath` 作为 `workspacePath`。创建并验证主要的用户可消费产物后，根 Agent 应主动呈现一次该主产物；普通源码、测试、配置、依赖元数据、临时文件与次要实现文件只保留在产物列表中，不自动打开面板。用户的明确要求和本轮 dismissal 始终优先。
