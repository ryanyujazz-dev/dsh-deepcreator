# @ryanyujazz/dsh-client-ui-browser

React-free Browser state store, native Surface host, and default Workbench Browser Presenter. The generic capability/claim loop and Presenter registry live in `@ryanyujazz/dsh-client-presentation`; this package contributes only `browser-tab`. The Host is authoritative and Browser state is refetched atomically after revisions. `getSnapshot()` is referentially stable between real publications, as required by React external stores.

Live presentation uses a staged handshake: panel render starts the mount, native bridge rejection is reported immediately, and only a completed mount plus visibility update acknowledges `presented`. Failures distinguish `PANEL_RENDER_TIMEOUT`, `SURFACE_MOUNT_REJECTED`, `SURFACE_MOUNT_TIMEOUT`, and `SURFACE_DESTROYED`. Replacing the panel means registering another Browser `PresentationProvider` and, for live pages, another Surface host.

The live Surface is mounted with the current panel-body rectangle, then measured again after the asynchronous native mount completes; later ResizeObserver updates keep the WebContents viewport equal to the panel width and height. This prevents the initial Workbench layout transition from leaving the page at a stale width.

Snapshot previews are hydrated independently from the atomic Browser state revision. A failed preview Remote is reported in the panel, retried with a bounded backoff, and can be retried explicitly; successful hydration publishes even when the Host revision did not change.

Workbench visibility and Browser resource lifetime are separate. Hiding the Browser Group only dismisses presentation and keeps its tabs alive. Closing an individual Browser instance tab calls the agent-fenced Browser Remote, closes the exact Provider page, and removes the logical `tabId` from `BrowserRuntime`.

The Browser Home header contributes a user-only new-tab action. It creates a blank persistent IAB tab through the Browser Remote and then presents that exact `browser-tab` through the independent Presentation client; a failed presentation rolls the new tab back, while success returns the exact `tabId` and activates it in the same click. The Presenter verifies a freshly fetched authoritative snapshot before publishing the Workbench instance route. Overlapping Browser refresh calls are serialized, responses for a no-longer-current Session are discarded, and the panel renders synchronization—not stale-page state—until the current Session snapshot arrives. An in-flight read therefore cannot manufacture a transient stale-page view. Live IAB instances expose a URL input whose submit action is network-policy checked by the Host and interrupts Agent control without granting it back. Every Home row also has an explicit close button: presented rows use the Workbench dismissal boundary, while unpresented rows call the same exact-tab Browser Remote directly.

All agent-fenced Browser Remotes (`state`, `newTab`, `navigateTab`, `closeTab`, and `snapshotImage`) receive the current `SessionId` as their first wire argument. The Client must mount the generated Browser contribution through `@ryanyujazz/dsh-client-workbench-remotes`; optional-method fallbacks indicate a genuinely older or disabled deployment, not a valid no-op path.

General Settings renders Browser configuration as its own top-level Browser group, alongside Preferences, with shared 72px row geometry and common Menu controls. The Browser Provider inventory stays collapsed by default: its summary row is the disclosure control, and opening it reveals 52px compact provider rows with availability and explicit install or repair actions without eagerly installing any Browser Pack or system integration.
