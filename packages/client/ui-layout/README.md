# @deepseek-ai/dsh-client-ui-layout

English | [中文](README.zh.md)

Shell plugin: three-column AppFrame (drag handles and concession chain) plus the `ctx.layout` panel-geometry service; it registers into the runtime-owned `root` slot and declares `sidebar`, `conversation`, `details`, `deepcreator.shell.sidebar-toggle`, and `shell.overlay`. The sidebar resize boundary is an invisible hit strip, while the details boundary retains its floating pill; only details shrinks during concession and then auto-closes. A closed sidebar contributes zero width and no residual rail. AppFrame instead seats its independent reopen control at the left of the conversation header, so its position is identical in the New Session hero and an active conversation. On macOS the red light begins at x=20, aligned with the New Session icon below; the wordmark begins at x=89, preserving the same 9px visible gap used between native buttons. The reopen button box begins at x=82 so its centered glyph shares that x=89 visible edge. The conversation header itself keeps 12px horizontal padding whether the sidebar is open or closed; only its title cluster receives the platform-safe reservation (98px on macOS, 32px elsewhere), leaving centered tabs unchanged. All controls share the 48px header's y=24 centerline. A maximized or fullscreen window hides the traffic lights, so the frame drops every macOS offset (wordmark spacing, reopen seat, title-cluster reservation) back to the base geometry while that state is reported. The frame marks a macOS Electron renderer and keeps a narrow top-edge drag fallback; the sidebar, conversation, and details owners use that same marker to make their full visible header whitespace draggable while excluding real controls. A Windows Electron renderer gets its own marker and a frame-owned 32px title strip above the three columns - base-palette background, mirrored window title (`DeepSeek Harness` suffix replaced with `DeepCreator`, product name fallback), whole-strip drag surface - because the native title bar is hidden behind the Window Controls Overlay on that platform; Linux retains only its system title bar. The package also seats the theme presenter: it consumes resolved `ctx.theme` snapshots and projects them onto the document (`html { color-scheme }` for native UA chrome, `body[data-ds-dark-theme]` from the active color scheme, `body[data-code-theme]` from the resolved Light/Dark code appearance, the theme's alias and code-font tokens as inline variables on body, and one owned `<meta name="theme-color">` whose content follows the computed body background). On the Windows Electron shell the presenter additionally resolves the base background and primary label tokens through an off-screen probe and pushes both colors over the `deepcreatorWindow.setTitleBarTheme` preload bridge after every apply, so the native caption buttons follow the in-app theme; values that are not concrete colors yet are skipped. Measuring after palette and token application keeps the rendered background as the single color authority; disposing the presenter removes its metadata node and probe with its other global writes.

AppFrame always mounts the conversation and details columns; a connected Session renders through `SessionProvider`. The layout store itself remains transient and owns only rendered geometry. The Workbench occupant restores its own session-persisted outer width through `ctx.layout.setWorkbenchWidth()`, while Hero/blank states derive a zero rendered details width without rewriting that preference. The details owner share reports resolved width, Stage width (Conversation + Workbench, excluding Sidebar), and pointer-resize gesture metadata. Conversation has a 360px concession floor while one Workbench column keeps a 150px floor; wider Workbench topology is resolved by its occupant. Focus geometry releases the ordinary third-column grid area, spans the full frame, then covers the Stage from the Sidebar edge to the right window edge. While Focus is active, toggling the Sidebar moves the details left edge with the same slow curve as the Sidebar grid track so the mounted Conversation cannot flash through between them; pointer resizing and reduced-motion mode remain immediate.

At phone widths (up to 640px), AppFrame projects those same occupants responsively: Sidebar becomes an overlay drawer, Conversation fills the center Stage, and an open details occupant overlays that Stage at full width. Each occupant retains an explicit grid-track assignment, so promoting Sidebar out of normal flow cannot shift Conversation into the zero-width sidebar track. Selecting another Session from the drawer closes it and returns to Conversation. No mobile-specific business component or route is introduced.

The details column is deliberately frameless. Its occupant owns all visible panel borders and insets, so AppFrame contributes only the invisible outer resize hit strip; Focus mode preserves the same ownership. The complete 8px strip starts at the Workbench root's left edge and extends inward, filling its 4px root padding plus the panel shell's 4px margin without intercepting the card or borrowing hit width from Conversation. The strip paints nothing at rest: while it is hovered or dragged, a full-height 1px line in the sidebar's border ink (`--dsw-alias-border-l1`) fades in on the true column boundary and fades back out when the pointer leaves.

The `/client` exports are the plugin body (`apply`/`inject`), `LayoutController`, and the owner-share interfaces. AppFrame, the panel store, and the concession solver remain package-internal.

## Model Experience

None, as the layout shell manages browser viewing state; nothing here reaches a model request.

#### KV Cache effect

None; this package neither assembles nor sends a provider request.

## Known Limitations and Deferred Work

- **Layout geometry is transient** — ui-layout never persists it. A composed Workbench may restore a session-scoped outer width into this service; without an occupant, details remains closed.
- **Concession-chain auto-close derives a zero width without touching the preferred width** — the panel restores itself when the window widens; consumers must not read the stored details width as the rendered truth.
- **No scroll anchoring during squeeze reflow** — layout changes may move the reader's viewport.
