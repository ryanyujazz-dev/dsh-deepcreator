# Workbench tool providers

Registers Review and Terminal panel types. Browser presentation is owned independently by `@ryanyujazz/dsh-client-ui-browser`; Artifact is owned by `@ryanyujazz/dsh-client-ui-workbench-artifact`. Review and Terminal render explicit unavailable states until their Host Remote packages are composed.

Provider views render Body content only. Refresh and Terminal create-tab actions are contributed to the public Workbench Panel Header.

The scope menu beside Review exposes Unstaged, Staged, and Uncommitted for Git workspaces, then an optional “Current turn” group and a “Historical turns” group whose unresolved `TURN N` entries sort newest-first. Non-Git workspaces show only those Turn groups and default to the newest live/retained Turn; the trigger itself stays concise as `TURN N`. Review remains one vertically scrolling expandable file list, and file headers no longer show Git status letters. Provider-defined Workbench presentation parameters carry `{ scope, turn, path, repository }`, so a mutation file reveal switches range, expands, and scrolls precisely. Nested repositories and submodules are atomic rows in Git scopes; clicking one drills down in the same panel, adds a returnable breadcrumb, and restores the parent scope, expansion, cache and scroll position on return. Turn menus stay session-global but filter to the current repository below the root. The canvas follows the Workbench shell while third-party themes contribute syntax and diff-highlight colors only.

One `ReviewCacheController` per session feeds both Review and conversation turn-change cards. The card registers into `deepcreator.conversation.chat.turnChanges`, immediately below the official produced-files selector chain, and shares `ConversationFileCard` chrome with the Artifact card without merging their rows or navigation. Review and the change card project only line-reviewable text: images/design files, PDF/Office documents, audio/video, archives, fonts, compiled artifacts and binary databases do not enter the change list. Host `presentation: binary` is authoritative, with known suffixes preventing a flash while deferred classification settles. Generated text, lockfiles, snapshots, minified source, notebooks and text data remain visible because provenance alone does not make a repository change unreviewable; nested repositories, submodules, symlinks, renames, modes and empty-file Git semantics remain visible too. The Host retains the complete repository truth for reconciliation and Undo. Every Review open, reveal, and scope-selection entry expands every reviewable file in the resulting scope. A nonzero unresolved turn card shows aggregate `+N -N`; its summary expands an inline per-file list with individual counts, while Review opens the owning Turn and a concrete unresolved mutation/list link eagerly mounts and scroll-focuses its target after that full expansion. Missing or still-settling turn metadata is never treated as proof that a file is resolved: mutation links stay on Review, including in non-Git workspaces; only an explicitly committed/reverted file opens Artifact. Line counts render only when the Host marks them available; empty, rename-only, mode-only, repository and submodule entries use explicit localized descriptions and never display `+0 -0`. A real summary failure appears as a non-blocking warning while status and per-file Diff remain usable; only the explicit old-Host missing-method response is silent. Cross-repository Turn cards retain all files and per-repository commit reconciliation but disable Undo with an explanatory tooltip. A turn committed before it ends never produces a card; an externally committed turn disappears after reconciliation, clears any selected historical Diff/source caches, and returns Review to Uncommitted.

Unstaged and historical Turns intentionally have different Diff bases: Index → Worktree versus Turn start → end, so the same file can carry different counts and changed lines across those scopes. On a hidden→visible open, the generic visibility catch-up refresh runs before the explicit presentation refresh, allowing the requested scope to win and drive deterministic full expansion.

Review consumes the Workbench `reveal` owner share: a `ctx.workbench.reveal('review', target)` presentation (the conversation's file-mutation rows) re-runs the status refresh with the target as the file to expand — matched by exact path, a rename's old path, or either-side suffix across absolute workspace and repository-relative forms — then lazy-loads its Diff, scrolls it to the top of the list, and revalidates it. An unmatched target (for example a change already committed) keeps the list and shows a one-line miss notice carrying the target.

The controller prefers `manifest/patches/source/probe` and automatically falls back when connected to an older Host. Official mutation and turn events drive refreshes; a precise write/edit refreshes and warms its affected path even while Review is hidden. A visible panel calls the in-memory probe every two seconds, while a hidden panel performs zero periodic RPCs. Generation, request ownership and local sequence guards discard late results after rapid scope/repository/viewport changes. Focus, viewport and directional overscan form separate patch priorities; leaving residency cancels queued work and releases unresolved ownership, so a scrollbar jump cannot wait behind an old screen. The initial response never retains complete old/new source, and opening an omitted-context FoldRow lazily loads only that file side. `@tanstack/react-virtual` mounts only file sections near the viewport with repository/scope-qualified path keys, conservative collapsed estimates, dynamic measurements, overscan and scroll anchoring; “expand all” remains logical rather than mounting every Diff body. Expansion or repository/scope changes reset offscreen estimates before paint and synchronously remeasure the bounded mounted window. The Review adapter additionally owns a disposable border-box observer for mounted absolute rows: this closes the same-commit viewport/row registration race where TanStack can cache a node before `targetWindow` exists. Accepted measurements now update the canvas height and sticky-safe `top` positions directly in the same DOM pass, rather than waiting for a later React render that can leave following rows at stale estimates while an async patch or wrapped line grows. Unified-patch parsing runs in a controller-owned Worker, and mounted hunks render as plain text before budgeted idle syntax highlighting completes. Status refreshes preserve unchanged entry identity, and manual refresh/turn-end checks retain their existing policy. The 500/2000-file fixtures assert that mounted sections and patch RPC volume remain viewport-bounded.

A text entry whose authoritative line statistics are nonzero but whose patch payload contains no renderable hunk displays an explicit retryable unavailable message. Review never presents that protocol mismatch as an unexplained blank expanded body.

Terminal Body uses an embedded xterm emulator connected to the Agent-fenced `system` PTY Remote. Keyboard data is delivered as ordered raw input, ANSI output is consumed incrementally with a monotonic cursor, and a `ResizeObserver` plus Fit addon keeps PTY rows/columns aligned with the Panel. Hiding a Group only removes visibility; it does not terminate the PTY. Legacy line-oriented sessions remain listable and closable but ask the user to create a new interactive terminal.

The first Terminal Group initialization opens a tab automatically: it restores a running terminal owned by the current Session when possible, otherwise it spawns one `system` PTY. This initialization is guarded per Session, so explicitly closing the final tab does not create a replacement; the Header plus creates additional terminals. Terminal has no management Home, back, SIGINT or separate kill button. Closing a Terminal tab immediately kills that PTY without confirmation; with no tabs, the Body shows only an empty state. Hiding the Terminal Group retains its tabs and processes. Tab pills are named after each PTY's working-directory project folder (duplicate names get a counter; sessions without a cwd fall back to the shell label, then the session id) and the group's accessible title carries the active PTY's shell program as a suffix, published through `contributePanelInfo()`.
