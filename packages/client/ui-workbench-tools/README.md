# Workbench tool providers

Registers Review, Terminal and user-facing Preview panel types; Preview retains the stable internal `browser` type id. Browser Web is usable for sandboxed loopback HTTP(S) previews. Review and Terminal render explicit unavailable states until their Host Remote packages are composed; they never invent business data or imply unsupported diff mutations. The artifact panel type moved to `@ryanyujazz/dsh-client-ui-workbench-artifact`, which owns the `artifact` type id and its session-event projection.

Provider views render Body content only. Refresh, Terminal control and create-tab actions are contributed to the public Workbench Panel Header; Review state and Preview URL entry are content, never a second subtitle toolbar.

The scope menu beside Review exposes Unstaged, Staged, and Uncommitted for Git workspaces, then an optional “Current turn” group and a “Historical turns” group whose unresolved `TURN N` entries sort newest-first. Non-Git workspaces show only those Turn groups and default to the newest live/retained Turn; the trigger itself stays concise as `TURN N`. Review remains one vertically scrolling expandable file list, and file headers no longer show Git status letters. Provider-defined Workbench presentation parameters carry `{ scope, turn, path, repository }`, so a mutation file reveal switches range, expands, and scrolls precisely. Nested repositories and submodules are atomic rows in Git scopes; clicking one drills down in the same panel, adds a returnable breadcrumb, and restores the parent scope, expansion, cache and scroll position on return. Turn menus stay session-global but filter to the current repository below the root. The canvas follows the Workbench shell while third-party themes contribute syntax and diff-highlight colors only.

One `ReviewCacheController` per session feeds both Review and conversation turn-change cards. The card registers into `deepcreator.conversation.chat.turnChanges`, immediately below the official produced-files selector chain, and shares `ConversationFileCard` chrome with the Artifact card without merging their rows or navigation. Every Review open, reveal, and scope-selection entry expands every file in the resulting scope. A nonzero unresolved turn card shows aggregate `+N -N`; its summary expands an inline per-file list with individual counts, while Review opens the owning Turn and a concrete unresolved mutation/list link eagerly mounts and scroll-focuses its target after that full expansion. Missing or still-settling turn metadata is never treated as proof that a file is resolved: mutation links stay on Review, including in non-Git workspaces; only an explicitly committed/reverted file opens Artifact. Line counts render only when the Host marks them available; binary, empty, rename-only, mode-only, repository and submodule entries use explicit localized descriptions and never display `+0 -0`. A real summary failure appears as a non-blocking warning while status and per-file Diff remain usable; only the explicit old-Host missing-method response is silent. Cross-repository Turn cards retain all files and per-repository commit reconciliation but disable Undo with an explanatory tooltip. A turn committed before it ends never produces a card; an externally committed turn disappears after reconciliation, clears any selected historical Diff/source caches, and returns Review to Uncommitted. Visible pages poll lightweight history/HEAD state at roughly two-second intervals to catch external commits.

Unstaged and historical Turns intentionally have different Diff bases: Index → Worktree versus Turn start → end, so the same file can carry different counts and changed lines across those scopes. On a hidden→visible open, the generic visibility catch-up refresh runs before the explicit presentation refresh, allowing the requested scope to win and drive deterministic full expansion.

Review consumes the Workbench `reveal` owner share: a `ctx.workbench.reveal('review', target)` presentation (the conversation's file-mutation rows) re-runs the status refresh with the target as the file to expand — matched by exact path, a rename's old path, or either-side suffix across absolute workspace and repository-relative forms — then lazy-loads its Diff, scrolls it to the top of the list, and revalidates it. An unmatched target (for example a change already committed) keeps the list and shows a one-line miss notice carrying the target.

Review is a viewport-driven continuous list with a prepared scroll frontier. One `ReviewCacheController` per session starts before the panel opens and fetches metadata/history only while hidden. A visible panel independently requests range `summary`, idle-preheats the first six bodies, and routes focus, near-viewport, and idle work through one priority queue with concurrency one. The scroll range initially contains those six files; reaching its loading sentinel fetches roughly two screens off-DOM, mounts their heavy bodies invisibly one per frame, and unlocks the complete batch only after both data and bodies are ready, so the scrollbar never enters partially loaded content. A direct file reveal starts a one-file window at that target and applies the same two-screen boundary independently above and below it. Files remain logically expanded; resident heavy bodies unmount 500 ms after leaving roughly three screens, retaining measured height by width bucket, controlled fold state, and scroll compensation. Resident/focused/interactive bodies are exempt from the 16-body soft limit. Raw patches/snapshots and Shiki tokens each use an approximate 32 MiB weighted LRU. Single-file completions notify only that path and totals; structurally unchanged two-second history polls publish nothing. Full-snapshot highlighting remains idle and progressive, but queued work is cancelled when its last resident block leaves. Status refreshes preserve unchanged entry identity, mutation tools invalidate through the same priority queue, and manual refresh/turn-end checks retain their existing policy.

Terminal Body uses an embedded xterm emulator connected to the Agent-fenced `system` PTY Remote. Keyboard data is delivered as ordered raw input, ANSI output is consumed incrementally with a monotonic cursor, and a `ResizeObserver` plus Fit addon keeps PTY rows/columns aligned with the Panel. Hiding a Group only removes visibility; it does not terminate the PTY. Legacy line-oriented sessions remain listable and closable but ask the user to create a new interactive terminal.

The first Terminal Group initialization opens a tab automatically: it restores a running terminal owned by the current Session when possible, otherwise it spawns one `system` PTY. This initialization is guarded per Session, so explicitly closing the final tab does not create a replacement; the Header plus creates additional terminals. Terminal has no management Home, back, SIGINT or separate kill button. Closing a Terminal tab immediately kills that PTY without confirmation; with no tabs, the Body shows only an empty state. Hiding the Terminal Group retains its tabs and processes. Tab pills are named after each PTY's working-directory project folder (duplicate names get a counter; sessions without a cwd fall back to the shell label, then the session id) and the group's accessible title carries the active PTY's shell program as a suffix, published through `contributePanelInfo()`.
