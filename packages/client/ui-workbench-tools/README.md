# Workbench tool providers

Registers Review, Terminal and user-facing Preview panel types; Preview retains the stable internal `browser` type id. Browser Web is usable for sandboxed loopback HTTP(S) previews. Review and Terminal render explicit unavailable states until their Host Remote packages are composed; they never invent business data or imply unsupported diff mutations. The artifact panel type moved to `@ryanyujazz/dsh-client-ui-workbench-artifact`, which owns the `artifact` type id and its session-event projection.

Provider views render Body content only. Refresh, Terminal control and create-tab actions are contributed to the public Workbench Panel Header; Review state and Preview URL entry are content, never a second subtitle toolbar.

Review is one vertically scrolling, expandable file list rather than a file-navigation/Diff split view. Each header carries the rename path and exact counts, sticks to the top of that one scroller, and is naturally pushed away by the next file header. Expanded staged and working-tree layers stay explicit, contextual hunks use the shared syntax-highlighted Diff primitive, binary changes use an explicit non-code state, and Review remains read-only.

Review consumes the Workbench `reveal` owner share: a `ctx.workbench.reveal('review', target)` presentation (the conversation's file-mutation rows) re-runs the status refresh with the target as the file to expand — matched by exact path, a rename's old path, or either-side suffix across absolute workspace and repository-relative forms — then lazy-loads its Diff, scrolls it to the top of the list, and revalidates it. An unmatched target (for example a change already committed) keeps the list and shows a one-line miss notice carrying the target.

Review is a warm data plane, not a cold list. One `ReviewCacheController` per session starts when the session becomes current — before any panel opens — and lives until the session leaves the list; it subscribes to the session's snapshot feed directly, so the panel is a pure `useSyncExternalStore` view. On entry it fetches status and prefetches every file's Diff sequentially in the background (capped; beyond the cap files fetch on demand), which is what makes first panel-open instant. Diffs parse once at fetch time (unified hunks merged with their source snapshots) and the parsed objects stay referentially stable, so re-renders never recompute a diff; a revalidate returning identical wire content reuses the previous parse outright. Parsing is the cheap part — hunk merging and row alignment, milliseconds. Full-snapshot Shiki highlighting is an atomic long task, so it is progressive, never inline: each snapshot (source text + language) highlights once through an idle-scheduled queue, all hunks of one file share that single tokenization, and a hunk whose snapshot is still queued builds plain-text rows. A DiffBlock mount jumps its snapshots to the front of that queue and subscribes; when the highlight lands, only the owning blocks rebuild with colors (the model memo's version folds in the highlight epoch). A status refresh merges instead of rebuilding: unchanged files keep their entry identity, caches and expansion, a moved XY/rename carries the cache forward marked stale, and departed files drop. Settled edit/write/bash tool results (read from the official snapshot nodes) invalidate after a debounce — a single edit targets its file, anything else marks the table — and the affected files revalidate through the same sequential queue, so later session changes are just background refreshes. The hidden→visible owner transition refreshes once as the catch-all for changes no event covers. Opening the panel expands every file and focuses the list at the top; a reveal-driven open (the conversation's file-mutation rows) keeps its own expand-and-scroll focus on the target instead of resetting. A user gesture (expand, reveal focus) fetches ahead of the queue. Ready caches evict oldest-first beyond a safety cap while expanded entries stay. Background refreshes are silent and never run `git diff --check`: checks run only on the manual refresh and when a turn ends (deferred to the next visibility refresh while hidden). Expanding a stale entry shows the cached Diff immediately and revalidates behind it. The Header carries one more action left of the refresh button - a single expand-all/collapse-all toggle whose glyph and action swap with the expansion state (harness-only unfold glyphs from ui-primitives), disabled with an empty file list. Expanding everything never freezes the main thread: as a file approaches the viewport while scrolling, only a light estimated-height skeleton mounts (scrolling stays on the compositor); the real DiffBlock fills in one per frame once scroll activity pauses for a pause window (a single-file expand is a gesture and fills immediately). Once mounted the body stays mounted — collapse hides it with CSS, so collapse→expand is a zero-rebuild flip — and anything not yet ready loads through the sequential queue instead of a concurrent burst.

Terminal Body uses an embedded xterm emulator connected to the Agent-fenced `system` PTY Remote. Keyboard data is delivered as ordered raw input, ANSI output is consumed incrementally with a monotonic cursor, and a `ResizeObserver` plus Fit addon keeps PTY rows/columns aligned with the Panel. Hiding a Group only removes visibility; it does not terminate the PTY. Legacy line-oriented sessions remain listable and closable but ask the user to create a new interactive terminal.

The first Terminal Group initialization opens a tab automatically: it restores a running terminal owned by the current Session when possible, otherwise it spawns one `system` PTY. This initialization is guarded per Session, so explicitly closing the final tab does not create a replacement; the Header plus creates additional terminals. Terminal has no management Home, back, SIGINT or separate kill button. Closing a Terminal tab immediately kills that PTY without confirmation; with no tabs, the Body shows only an empty state. Hiding the Terminal Group retains its tabs and processes. Tab pills are named after each PTY's working-directory project folder (duplicate names get a counter; sessions without a cwd fall back to the shell label, then the session id) and the group's accessible title carries the active PTY's shell program as a suffix, published through `contributePanelInfo()`.
